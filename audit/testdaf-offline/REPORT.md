## T5 checkpoint
New shared engine module `german_exams/result.py` implements module-separated results with three explicitly distinct kinds, so a profile without a published raw-to-scaled conversion can never be shown an invented official score: `practice_raw_result` (plain item correctness, always available), `official_style_scaled_result` (points/maxPoints/optional pass, computed only from a caller-supplied verified `ScoringSpec` via the existing `raw_to_points`/`is_pass`, returns `None` otherwise), and `practice_formative_result` (writing/speaking task coverage — a count, never a score). `build_module_result()` assembles exactly one module's result from these and raises if given neither objective nor productive data; there is no function anywhere in the module that accepts more than one module's data (asserted by introspecting every function's parameters in a dedicated test), so a combined exam-wide PASS/FAIL is structurally impossible, not just avoided by convention.

Because every TestDaF `PartBlueprint.scoring` is `None` (no published raw-to-scaled conversion — see testdaf_digital.py's own `rawToScaledConversionAvailable: False`), `official_style_scaled_result(None, ...)` returns `None` automatically for TestDaF once its objective parts are eventually released, with no TestDaF-specific check anywhere in this module — the gate is the presence of a verified `ScoringSpec`, exactly the same mechanism TELC/Goethe already use. No TDN classification function exists: TDN bands describe official 0-20 scaled-score ranges (see `TDN_BANDS`/`SCORING_METADATA` in testdaf_digital.py, unchanged, still descriptive-only), but the raw-item-count -> scaled-score conversion is not published anywhere verified, so no function here computes or labels one — implementing it would require the same official source testdaf_digital.py's docstring already flags as missing.

Mirrored on the frontend as `frontend/js/features/german-exam/module-result.ts`: `validateModuleResult` rejects a result missing both `objective`/`productive`, an `official` result with no backing `objective` result, an impossible correct/total or partsCompleted/totalParts pair, and (defensively) any `tdn`/`scaledScore`/`rawScore` key on the official result or `score`/`points`/`tdn`/`scaledScore` key on the productive result. `renderModuleResult` shows raw correctness (with percent when available), the official-style score only when present, an explicit "No official scaled score is available for this exam yet" note when a module has objective results but no verified scoring, and formative coverage for writing/speaking — never a numeric score. `renderExamResultSummary` renders one independent `<section>` per module and never renders a combined verdict (asserted directly: no "overall"/"final result"/"pass/fail" text anywhere in its output).

14 backend tests (`test_german_exam_result.py`) and 6 browser tests (`module-result-browser.spec.mjs`) passed. Frontend typecheck passed; full german_exam* + german_learner_profile + german_practice backend suite (692 cases) passed, no regression.

Release blockers: this is result *representation* only — nothing here yet reads real attempt data from `german_exam_attempts`/writes a module summary automatically; a future wiring step (T6's exam-session final summary, or a dedicated results endpoint) must call `build_module_result`/`renderModuleResult` with real aggregated counts. No TestDaF part is scored by this or any other change in this phase.

## T6 checkpoint
Full-exam-simulation architecture, generic across every profile. Backend: a new `DeliveryPolicy` dataclass (`fixedTaskOrder`, `backNavigationAllowed`, `additionalUnscoredTrialTasks`) on `shared.py`, an optional `delivery_policy` field on `ExamProfile` (None = today's unchanged free-navigation/no-timer behaviour), and `manifest.py` now serialises it generically as `deliveryPolicy`. `TESTDAF_DIGITAL.delivery_policy` is wired from the existing `DELIVERY_METADATA` dict in testdaf_digital.py (previously computed but unused — now actually consumed), so the single-file-of-facts rule holds: `DELIVERY_METADATA` is still the only place these three TestDaF facts are edited. TELC/Goethe are untouched and their manifests now correctly serialise `deliveryPolicy: null` (asserted directly against `GERMAN_EXAM_PROFILES`, not a TestDaF-specific check).

Frontend: `frontend/js/features/german-exam/exam-session.ts` (`ExamSession`) is a pure state-machine class — no DOM, no owned timer/interval — driven entirely by `manifest.deliveryPolicy` and an injectable `now()`/`Storage`, so it is trivially unit-tested with a fake clock. It implements: per-part `submissionState` (not_started/in_progress/submitted/expired) and answer tracking; `canNavigateTo`/`goToPart` enforcing `fixedTaskOrder` (must submit the current part before advancing, one step at a time) and `backNavigationAllowed` (a completed part becomes unreachable when false); a per-module countdown (`remainingModuleSeconds`) that starts the first time a module is entered and never resets; `tick()`, called by the caller's own timer, which auto-locks a module whose deadline has passed — marking every not-yet-submitted part `expired` and auto-advancing into the next module; `hasUnsavedRisk()` for refresh/close protection (true only while the current part is `in_progress`, e.g. an active recording, not after submission — autosave already covers everything else); JSON snapshot autosave to an injected `Storage`, scoped by `profileId:profileVersion` so a structural change never resumes into a stale part index, and a corrupted snapshot falls back to a fresh session instead of throwing; and `finalSummary()`, which reports only the modules actually completed and labels `additionalUnscoredTrialTasksInOfficialExam` explicitly rather than ever fabricating extra trial tasks — there is no function anywhere in this class that combines more than one exam session, matching T5's module-separation rule.

2 new backend tests in `test_german_exam_profile_testdaf_digital.py` (`test_delivery_policy_is_wired_from_delivery_metadata_and_exposed_on_the_manifest`, `test_a_profile_without_a_delivery_policy_gets_a_null_manifest_field_not_a_default_guess`, file now 30 cases total) and 12 frontend tests (`exam-session.test.mjs`, fake-clock-driven: fixed-order gating, back-navigation gating, free-navigation fallback, module-timer expiry/auto-advance, a module with no duration never expiring, autosave/resume, corrupted-snapshot recovery, profile-version-scoped recovery, unsaved-risk detection, finish-and-lock-out-further-navigation) passed. Full german_exam*/german_learner_profile/german_practice backend suite (694 cases) and full frontend unit suite (804 cases, only the 2 pre-existing unrelated TS-registry-mirror failures from before this branch) passed. Frontend typecheck passed.

Release blockers: `ExamSession` is not yet wired into `exam-workspace.ts`'s free-practice UI (that UI intentionally stays free-navigation/untimed — a full-exam simulation is a distinct mode, not built here) or rendered against `module-result.ts`'s summary components; both are natural next steps once real generation is live. No TestDaF part is enabled by this change; `additionalUnscoredTrialTasks=True` remains a label only — no trial tasks are generated or simulated.
